# Pan Daily Briefing

Follow [`system/daily-briefing.md`](../../system/daily-briefing.md) end to end.
Read the complete live GitHub Issue/Project set, Project order, every workstream,
declared backlogs, and optional Domain planning context. Stop on incomplete
pagination or lifecycle/revision conflicts.

Recommend a realistically sized Today set before asking the user to review it.
Today may contain any mixed task receiving agreed human attention. Needs me
does not automatically mean Today. Past dates stay unresolved until explicitly
reconsidered; future means bring human attention back; empty means unscheduled.
Deadlines and recurrence cadence are separate. Dates never gate or sort AI.

Use the review UI only as a draft/approval surface. Publish the complete
proposal, show its URL, wait for the matching revision, and apply date/guidance
writes only after explicit approval. Re-read expected task revisions, write
durable guidance first, increment revisions last, and verify every write.
